# Planet Render 360 — Real-Location Fidelity Redesign

> **Goal:** Redesign / greatly improve the architecture so the 360° render looks as much like the **real location** as possible — same terrain silhouette, same street/block fabric, same building heights/roofs/colours, same water/roads/vegetation, same landmark at its true bearing/scale — while staying smooth on mobile, free-data-only, no self-hosted server, no paywall.
>
> **Generation-time decision (user, 2026-10-28):** A 1–2 minute generation is totally fine, especially on Ultra. Spend that time on fidelity (more/larger fetches, finer grids, real footprints, PBR/AO baking, LOD/impostor baking) instead of cutting corners to be fast. Frame rate once inside the view must still be smooth — generation time and frame time are different budgets. See §3.1 for the per-tier time budgets every task must plan against.
>
> **How to use this file:** This is the shared tracker for multiple AI agents (and humans). Claim a task before starting it, tick it only when its validation passes, and never tick a task on another agent's word alone. See §2 for the coordination protocol.
>
> **Companion docs:** [architecture plan](2026-10-27-planet-render-360-architecture.md) · [data-source register](../../docs/data-source-register.md) · [visual PRD](../../visual-plan/PRD.md) (`visual-plan/PRD.md` §§3–4, AC-01…AC-18 remain the visual target; this plan is the architecture to actually reach them).

## 1. Why the current render cannot look like the real place (diagnosis)

Grounded in the code as of 2026-10-28. Each item names the owning file/symbol so a fix can be claimed precisely.

| # | Root cause | Evidence (file : symbol) | Effect on fidelity |
|---|---|---|---|
| D1 | **Vertical scale is invented, not real.** Total relief is remapped to ~30 world units regardless of place. | `scripts/generation/pipeline.gd` : `_fetch_dem` (`vscale = clampf(30.0 / maxf(mx-mn,1.0), 0.02, 0.35)`) | Alps and Paris read at the same height. Slope, skyline, and horizon are wrong everywhere. |
| D2 | **Detailed world is tiny.** 220 world units at `METRES_TO_WORLD = 0.25` ≈ 880 m across; everything beyond is a hazy apron/silhouette ring. | `scripts/generation/terrain_builder.gd` : `WORLD_SIZE`, `METRES_TO_WORLD`, `_far_ground`, `_city_silhouette` | Real fabric stops after ~400 m. Distant districts, river continuation, and landmark context are procedural filler. |
| D3 | **DEM window is coarse.** One Terrarium tile at zoom 12, a fixed 144 px window resampled to the preset grid. | `scripts/data/dem_fetcher.gd` : `ZOOM=12`, `_emit_from_image` (`step_px = 144.0 / grid`) | At Ultra the grid is finer but the source pixels are not — no new detail, only interpolation. Near-field relief (quays, valleys, ridges) is smoothed away. |
| D4 | **TerrainBuilder is a 1000-line monolith at the hard limit.** Terrain, water, buildings, roofs, roads, vegetation, landmarks, materials, and satellite UVs all live in one class. | `scripts/generation/terrain_builder.gd` (1000 lines; `tools/check_class_size.sh` limit) | No change can be made safely in isolation; agents collide on one file; no unit can be tested or LOD-swapped alone. |
| D5 | **Buildings are axis-aligned boxes.** OSM footprints are reduced to centre + `size_x/size_z` (AABB), rotation and polygon shape are discarded. Height falls back to `building:levels * 3.2` or a 10 m default. | `scripts/data/osm_fetcher.gd` : `parse_features` (building branch); `terrain_builder.gd` : `_real_buildings`, `_building` | Rotated Haussmann blocks, L-shaped buildings, courtyards, and street alignment are lost. Every block reads as a generic slab. |
| D6 | **One facade texture for every building on Earth.** A single procedural limestone texture (6 storeys × 6 bays) tinted 6 ways. | `terrain_builder.gd` : `_facades` | Paris, Tokyo, and Cairo share a facade. No brick, concrete, glass, wood, or regional material; no per-building window count from real floors. |
| D7 | **Satellite drape is low-res and stretched.** 3×3 tiles at zoom 16 (~1.2 km) stretched over the detailed terrain; used as albedo with only a slope shade. | `scripts/data/satellite_fetcher.gd` : `SPAN=3`, `_stitch`; `terrain_builder.gd` : `satellite_uv`, `_terrain_mesh` | Roofs/roads blur, drape streaks over the compressed DEM (PRD Polish-round-1 known gap), and ground truth disagrees with the extruded buildings on top of it. |
| D8 | **OSM fetch radius and parsing are narrow.** `RADIUS_M = 420`, `out geom 900` cap; only `building/highway/natural/landuse/leisure=park` plus a small `man_made` set. No `building:colour`, `roof:colour/shape/material`, `addr`, waterway lines, bridges, rail, coastline detail, or tree nodes. | `scripts/data/osm_fetcher.gd` : `build_query`, `RADIUS_M` | The data needed to *match* a real place is never fetched, so generation invents it procedurally (`_buildings`, synthetic `_river_path`). |
| D9 | **Procedural fallback fights real data.** Synthetic S-curve river, procedural Haussmann infill, and silhouette ring run even alongside OSM data and can contradict it. | `terrain_builder.gd` : `_river_path`, `_buildings`, `build_world` | Rivers where none exist, blocks over real streets/parks, doubled fabric. Fallback must be *absence-only*, never additive over real data. |
| D10 | **Landmarks are scaled/clamped for framing, not placed truly.** Site is clamped to ≤95 units and rescaled `sqrt(pos/site) * 1.9` for apparent size. | `terrain_builder.gd` : `landmark_world_pos`, `_landmark` | Landmark distance, apparent size, and occlusion vs. neighbours are wrong by construction. |
| D11 | **No material / texture system.** Speckle-noise procedural textures only; no PolyHaven-class PBR sets, no normal/roughness/AO pipeline, no texture atlas or per-class material library. | `terrain_builder.gd` : `_speckle`, `_detail_texture`, `_slate`, `_facades` | PRD §3.1 (PBR on 100% of surfaces, no flat reads at Fidelity 2–3) is unreachable. |
| D12 | **No LOD / streaming / instancing architecture.** Per-building `MeshInstance3D` boxes, per-tree nodes, budgets are counts in `RenderSettings`, not LOD rings or `MultiMesh`. | `terrain_builder.gd` : `_building`, `_broadleaf`, `_vegetation`; `scripts/render/render_settings.gd` | Raising fidelity raises draw calls linearly. Fidelity and frame rate are in direct conflict with no structural escape. |
| D13 | **Lighting/atmosphere is a fixed golden-hour grade for every place.** One sun/fog/sky rig, ACES exposure baked in `View360`. | `scripts/screens/view_360.gd` : `_build_3d`, `_apply_time`, `_build_clouds` | Correct for the Paris PRD capture; wrong for overcast Reykjavík, desert noon, or a place whose identity *is* its light/climate. Weather/season exist but do not drive materials/terrain. |
| D14 | **No fidelity measurement.** Tests assert contracts (parsers, budgets, flow), not resemblance. No golden-location image/height/footprint comparison gates a change. | `tests/` (`scenery_test.gd`, `screenshot_test.gd` are the closest) | "Looks more real" is unreviewable; regressions in resemblance ship silently. |

**Non-goals (unchanged hard constraints):** no self-hosted server/proxy, no paid/keyed data source, no paywall, Godot 4.7 + GDScript only, every class under `scripts/` ≤ 1000 lines (`tools/check_class_size.sh`), mobile-smooth once rendering (Fidelity 1 ≥ 30 fps on a mid-tier phone per PRD §3.4). Generation time is **not** a reason to cut fidelity on High/Ultra — see §3.1 (Ultra may take 60–120 s cold).

### 2.2 Claiming and tracking rules

- [ ] Before starting a task, change its line prefix from `- [ ]` to `- [~]` and append ` — @<role>/<session-name> <YYYY-MM-DD>`. Example: `- [~] T1.2 … — @A/natural-fenrir 2026-10-28`
- [ ] On completion, change `- [~]` to `- [x]` **only after** the task's *Validation* line passes locally, and append the evidence (test name + capture/fixture path). Example: `— done @A 2026-10-29, dem_test.gd PASS, tile z14 Paris sample 2.4 m/px logged`
- [ ] If blocked, change to `- [!]` and add a `> BLOCKED:` note directly under the task with the blocker and who must unblock it. Do not leave a task in `[~]` across sessions without a note.
- [ ] One task = one focused commit-sized change. Never bundle two task IDs in one edit. Never commit/push unless the user explicitly asks (per `AGENTS.md`).
- [ ] **File-ownership rule:** only the owning role edits a file listed in §2.1. A cross-cutting need becomes a new task for the owner, not a drive-by edit. `terrain_builder.gd` is frozen for new features from Phase 1 onward — new work goes in the new builder classes (Phase 1, T1.1).
- [ ] **Contract-first rule:** any change to `LocationData` fields, `GenerationPipeline` stage order, or `RenderSettings.Preset` semantics requires a Phase 0 contract task (T0.3) to be `[x]` first, and all consuming roles must re-read the contract before editing.
- [ ] **Class-size rule:** run `tools/check_class_size.sh` after every task that adds/grows a class. A task that pushes a file over 1000 lines is not done — split first, then tick.
- [ ] **No-faked-fidelity rule:** procedural fallback may run only when real data for that layer is absent (fixes D9). Any task adding fallback must add the absence check in the same task.

### 3.1 Generation-time budgets — spend time on fidelity (user decision, 2026-10-28)

Generation (picker → first usable 360° frame) and frame rate are **separate budgets**. A slow-but-faithful build that then runs smoothly beats a fast build that looks wrong. Agents must not reject a fidelity technique only because it is slow to *generate* if it fits the tier budget below and does not hurt *frame* time (Phase 7 still owns frame time).

| Tier (current → PRD) | Cold generation budget (broadband, uncached) | Cached revisit target | What the extra time is *for* (examples, per task) |
|---|---|---|---|
| Fast (Fidelity 1) | ≤ 20 s | ≤ 3 s | Coarser DEM/satellite zoom, near ring only, no AO bake |
| Balanced | ≤ 45 s | ≤ 5 s | z14 DEM mosaic, z16 satellite, full footprints in near ring |
| High — default (Fidelity 2) | ≤ 75 s | ≤ 5 s | z14 DEM + z17 satellite, rich OSM tags, PBR sets, merged mid ring |
| Ultra (Fidelity 3) | **60–120 s acceptable; hard cap 150 s** | ≤ 8 s | Largest DEM/satellite mosaics (z18 where available), second OSM ring query, per-building roof/material sampling, AO/contact-shadow bake, texture-atlas + MultiMesh + impostor baking, far-ring continuation |

Rules for every agent:

- [ ] Plan each generation task against its tier's cold budget above; record measured stage times in the task evidence (fetch / GroundTruth / build / bake / first frame). A task that fits Ultra's budget must not be simplified to meet Fast's.
- [ ] The loading screen must earn a 1–2 minute wait: real per-stage progress, what is being fetched/built, elapsed + stage estimate, and cancel that returns to the picker within 1 s at any point (`scripts/screens/loading_screen.gd`, `GenerationPipeline` stage signals). No fake timers as the only progress.
- [ ] Show a usable preview as early as the data allows (e.g. terrain + satellite drape first, then buildings/vegetation/landmarks populating) *only if* it does not change the final layout — preview is the same `GroundTruth`/builders at lower completeness, never a different procedural scene.
- [ ] Cache aggressively (Phase 2, T2.5) so the 1–2 minute cost is paid once per place/tier; changing only time/season/weather must never repay it.
- [ ] If a stage would exceed the tier's hard cap, degrade that *layer* explicitly (register fallback order: lower zoom → smaller radius → cached → procedural-absence-only) and log it on the loading/attribution UI — never silently drop the whole place to procedural.
- [ ] Frame-time budgets are unchanged: Fidelity 1 ≥ 30 fps mid-tier phone, ≤ 400 draw calls (PRD §3.4/§6). Generation time may buy *precomputed* fidelity (baked AO, atlases, merged geometry, impostors) precisely so frame time does not pay for it.

**Key invariants (every phase must preserve):**

1. **True scale:** heights, footprints, distances, and landmark placement in real metres end-to-end. Vertical exaggeration, if ever used, is a *view* option in `AtmosphereRig`/`CameraRig`, never baked into `WorldModel` data. (Fixes D1, D10.)
2. **One ground truth:** terrain mesh, buildings, roads, trees, water, and landmarks all sample the same `GroundTruth` surface. No builder computes its own heights. (Fixes D2/D9 class of bugs.)
3. **Real data first, procedural only on absence** — per layer, independently (real buildings + procedural trees is fine; procedural river over a real river is not). (Fixes D9.)
4. **Contracts before visuals:** fetchers normalise into `LocationData`/`WorldModel`; generation never parses provider payloads.
5. **Fidelity scales by LOD/texture/shadow, never by layout:** changing quality preset must not move any object or change any hue by >2% (PRD §3.4, AC-12).
6. **Every class ≤ 1000 lines;** new responsibilities get new focused classes instead of growing existing ones.
7. **Generation time buys fidelity (§3.1):** within the tier's cold budget (Ultra 60–120 s), prefer the more faithful option — larger mosaics, full footprints, baked lighting/AO, atlased PBR, precomputed LOD/impostors. Never spend that budget on per-frame cost.

## 14. Risks and open questions

- [ ] **R1 — Overpass reliability/caps.** Wider radius + richer tags increase query cost on a free, load-sensitive service (502s already observed). *Mitigation in-plan:* tiered radius queries, aggressive cache (T2.3/T2.5), register-compliant identification. If caps still block ≥800 m, the fallback is two smaller queries, never a proxy (hard constraint).
- [ ] **R2 — Satellite/DEM resolution ceiling.** Free zoom-17/18 imagery and z14 DEM still cap near-field detail (roof furniture, narrow streets, small watercourses will remain approximate). The scorecard (T0.2) must state this ceiling per tier so AC-18 is judged honestly.
- [ ] **R3 — Texture licensing/footprint.** CC0 PBR sets add asset size; mobile download/storage budget must be set in T4.3 (atlas + resolution per tier) or the app grows unbounded.
- [ ] **R4 — Metre-scale world vs. mobile GPU.** A 2.4 km detailed extent at true scale pressures vertex counts and shadow reach. *Mitigation:* LOD rings + instancing (Phase 7) are not optional polish — Phase 3/4 captures must record triangle/draw counts from the start so Phase 7 is sized by evidence.
- [ ] **R6 — 1–2 minute wait UX (Ultra).** The §3.1 budget is only acceptable if the wait is legible: real stage progress, cancel within 1 s, early preview, and a cached revisit in seconds. A static/fake progress bar for 2 minutes is a defect even if the final render is faithful. *Mitigation:* T7.5 validation includes interrupting a live Ultra build and timing the cached revisit; settings copy (T7.4) sets the expectation before the user picks Ultra.
- [ ] **R5 — Regional building defaults.** Inferring facade/roof/floor-height by region (T4.2/T4.3) can stereotype wrongly where OSM is sparse. Defaults must be data-derived from nearby real buildings where any exist (T4.5), with the table documented and reviewable.
- [x] **Open Q1 — Detailed extent per preset.** 2400 m is the Phase 1 default; confirm against device profiling in T7.1 (may become e.g. 1600 m Fast → 3200 m Ultra). Owner: E. Needed by: T3.1. — settled @E+B 2026-10-28 (T7.0/T7.1): 2400 m on every preset; presets differ only in LodRing radii, terrain mesh density, building caps, shadows (AC-12).
- [ ] **Open Q2 — Fidelity tier naming.** Keep shipping names (Fast/Balanced/High/Ultra) or adopt PRD names (Fidelity 1/2/3)? User-facing decision; settle in T7.4 with the settings screen copy. Owner: E + user.
- [ ] **Open Q3 — Reference photos for non-Paris golden locations.** T0.5 needs licensed/user-provided imagery or those locations score geometry-only. Owner: F + user.
